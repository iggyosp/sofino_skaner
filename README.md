# Софьино — сканер

Для сотрудника: открыть сайт → ввести ФИО и текущее местоположение → включить камеру → сканировать. Пароля, ключа и настроек подключения в интерфейсе нет.

## Однократное подключение таблицы владельцем

1. Откройте свою Google Таблицу с листом «Сканер» → **Расширения → Apps Script**.
2. Вставьте код из `Code.gs`. Если в проекте уже есть другой рабочий код, предварительно сохраните его и проверьте конфликты имён.
3. Выберите функцию **setup** → **Выполнить**, разрешите доступ вашему проекту. Таблица определится автоматически; вводить её ID или ключ не нужно. В столбце E появится «Исходный код», в F — «ID записи» для защиты от повторной отправки. Первые четыре заголовка сохраняются: «Дата и время», «Сотрудник», «Зона / маршрут», «Код». Местоположение записывается в третий столбец. Существующие строки не очищаются.
4. **Развернуть → Новое развертывание → Веб-приложение**. Выполнять от имени: **Я**, доступ: **Все / Anyone**. Скопируйте полученный адрес с окончанием `/exec` в поле `endpoint` файла `config.js` этого репозитория. Если обработчик уже развёрнут, обновите его код и выберите новую версию через управление развертываниями.
5. GitHub: **Settings → Pages → Deploy from a branch → main → /(root) → Save**. Адрес после публикации: https://iggyosp.github.io/sofino_skaner/ .

Сотрудникам нужна только ссылка на приложение. Развёртывание Google выполняется один раз владельцем. Без настроенного endpoint сканирования сохраняются на телефоне, но не поступают в таблицу.

## Проверка

Откройте сайт на телефоне в Chrome/Safari, введите ФИО и местоположение. Разрешите камеру и отсканируйте тестовую этикетку. Дождитесь подтверждения и проверьте строку в таблице. Повторите с отключением и восстановлением сети на уже открытой странице: повторная отправка одного события не должна добавлять вторую строку.

`node tests.cjs` проверяет отправку без ключа, повтор одного события, очередь при сетевой ошибке, подтверждения записи, ведущие нули и защиту от формул. Эти проверки не заменяют реальный запуск камеры и Google Apps Script.

## Поведение

- ФИО и местоположение сохраняются на телефоне. Их можно изменить в любое время для следующих сканирований. Записи уже в очереди сохраняют исходные данные.
- Отправка автоматическая: при сканировании, восстановлении сети и каждые 30 секунд, пока страница открыта. Неотправленные записи переживают перезагрузку. Полноценного офлайн-запуска и фоновой отправки после закрытия страницы нет.
- История, резервная копия и очистка подтверждённых записей находятся в раскрываемом блоке. Очистка не удаляет записи из таблицы. При изменении данных другой вкладкой текущая блокируется; используйте одну вкладку на телефоне.
- Дубликаты товара проверяются в пределах одного местоположения на одном телефоне до очистки отправленных. Между телефонами товарные дубли не проверяются. Столбец F предотвращает только повтор одной сетевой отправки.
- Код сохраняется текстом. Алгоритм Мартинкевича доступен через общую настройку `decodeMartinkevich` в `config.js`; включён для ваших этикеток.
- Время берётся с телефона, таблица использует московский часовой пояс.
- По запросу владельца приём записей открыт без пароля: любой, у кого есть адрес приложения или обработчика, может отправить запись с произвольным ФИО. Чтение таблицы через обработчик не реализовано; права Google Таблицы не меняются.
- Адрес таблицы не публикуется в репозитории. setup сохраняет его в свойствах проекта автоматически. Ограничения Apps Script и чтение столбца ID делают это решением для небольшой команды.
- Старое хранилище scanner_routes не отправляется автоматически: в нём нет даты и ФИО. Оно включается в резервную копию JSON; автоматический импорт копии не реализован.

## Исходный код в E

D — преобразованный номер; E — точный текст, полученный от сканера до обрезки префиксов и декодирования; F — служебный ID. Обновите Code.gs, выполните setup и разверните новую версию. setup вставляет E перед прежним столбцом ID, сохраняя старые ID в F. Для прежних записей исходный текст неизвестен, E остаётся пустым. Новая версия сканера сохраняет его локально и ждёт версии 2 обработчика перед отправкой. Затем обновите страницу сканера.

## Ручное создание кода

В поле «Ввести числовой код вручную» можно ввести номер от 0 до 1099511627775 и нажать «Создать». D получает введённый номер, E — новый код. ФИО и местоположение нужны для сохранения. Результат также показывается в поле для копирования.

Формат генерации: префикс *, Base64 из шести байт; первые пять — числовой ID в big-endian, шестой — 0. Этот формат обратно декодируется нашим алгоритмом в введённое числовое значение. Ведущие нули сохраняются в D, но не кодируются в числе. Восстановить оригинальный шестой байт, префикс и оформление по одному ID невозможно. Созданный код не гарантированно принимается внешней WMS: её требования к шестому байту неизвестны. В E для ручного ввода хранится синтезированный код, а для камеры — считанный исходный текст. Ручной ввод работает через существующий обработчик версии 2; обновление Apps Script для этого изменения не требуется.
